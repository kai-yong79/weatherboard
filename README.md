## 된 기능과 확인 결과

아래 기능은 코드에 구현되어 있습니다. 사용자가 직접 확인했다고 남긴 결과가 없으므로 상태는 모두 **미확인**으로 기록합니다. 개발 도구 검증 결과를 사용자 확인으로 대신하지 않습니다.
배포 등록은 사용자가 알려 주었으며, 최신 배포의 기능별 동작은 미확인입니다.

| T-번호 | 구현된 기능 | 사용자 확인 결과 | 확인할 내용 |
| --- | --- | --- | --- |
| T-01 | 기본 일정 목록 조회 | 미확인 | 최초 DB 설정 후 기본 가상 일정 6건이 보이는지 |
| T-02 | 일정 추가·DB 저장 | 미확인 | 가상 일정 추가 후 새로고침해도 유지되는지 |
| T-03 | 지역별 오늘 날씨 | 미확인 | 세종·대전·태안·보령 일정의 최고 기온·최대 풍속(m/s)·강수확률이 표시되는지 |

| T-07 | 오늘 판단 md 다운로드 | 미확인 | `현장일정_판단_YYYY-MM-DD.md`의 표가 화면과 같고 마지막 줄에 판단 기준이 있는지 |
| T-08 | 여러 브라우저의 일정 공유 | 미확인 | 다른 브라우저에서 같은 배포 주소를 열거나 새로고침하면 추가한 일정이 보이는지 |
| T-09 | DB 지역·구분 값 제한 | 미확인 | 허용되지 않은 지역·구분으로 저장하면 DB가 거부하는지 |

이전 JSON 단계의 T-06(파일 읽기 실패 시 배포 주소 안내)은 현재 Supabase 방식의 확인 대상에서 제외합니다. 과거 사용자 확인 결과도 미확인입니다.

## 알려진 문제

- 사용자 브라우저에서 발생하는 오류 여부는 미확인입니다. 개발 중 실제 Supabase 조회는 정상 응답했지만, 사용자 화면에서의 추가·공유·다운로드 확인은 남아 있습니다.
- 다른 사람이 추가한 일정은 새로고침해야 보입니다. 현재 일정 수정·삭제와 실시간 동기화 기능은 없습니다.
- 로그인 없이 공개 방문자가 조회·추가할 수 있으므로 개인정보 없는 가상 일정만 사용합니다.
- 인터넷이나 외부 API·스크립트 장애로 일정·날씨 조회가 실패할 수 있습니다. 저장 완료를 확인하지 못했다는 안내가 나오면 새로고침해 목록을 확인한 뒤 재입력합니다.
- 기존 브라우저 추가 일정은 DB로 자동 이관하지 않습니다. `data/tasks.json`은 이전 단원 참고용이며 현재 화면에서는 읽지 않습니다.

## 실행과 Supabase 설정

1. Supabase SQL Editor에서 [setup.sql](setup.sql) 전체를 실행합니다. 표 생성·값 제약·RLS 정책·가상 일정 6건을 설정합니다. 재실행 시 기존 데이터를 지우지 않으며, 빈 표에만 기본 일정을 넣습니다.
2. [config.js](config.js)의 두 줄에 프로젝트 주소와 공개용 키(publishable 또는 기존 anon)를 설정합니다. secret·service_role 키는 사용하지 않습니다.
3. 배포 주소 또는 `index.html`을 엽니다. Supabase와 날씨 조회에는 인터넷 연결이 필요합니다.

T-09는 SQL Editor에서 아래 검증문을 각각 실행합니다. 제약 오류가 나며 잘못된 행이 저장되지 않아야 합니다.

insert into public.wx_tasks (title, region, kind, owner)
values ('제약 검증', '서울', '야외', '가상담당');
